# AXmiPic

軽量で信頼性の高いセルフホスト型の画像ホスティングサービスです。画像のアップロード、オンデマンドの画像処理、複数のストレージバックエンド、管理コンソールを提供します。バックエンドは単一の Go バイナリ、フロントエンドは埋め込みのシングルページアプリケーションです。

> 📖 完全なドキュメント: **[ドキュメントサイト](https://axmipic.gpcn.cc/)**（英語・デフォルト） · **[日本語](https://axmipic.gpcn.cc/ja/)** · **[中文](https://axmipic.gpcn.cc/zh/)**

## 機能

- **多彩なアップロード方法**：管理画面からのアップロード、一括アップロード、貼り付けアップロード、ドラッグ＆ドロップ、`multipart` API、オブジェクトストレージへの署名付き直接アップロード
- **X リンクのインポート**：X の投稿 URL を貼り付けるだけで作者と画像を解析します。無料の fxtwitter API または X 公式 API に対応し、画像広場へ直接公開するか、まず非公開にするかを選択できます。作者名と元投稿のクレジットは自動的に保持されます
- **ワンクリック埋め込みコード**：画像の URL、HTML、BBCode、Markdown をコピーできます（ロールの機能スイッチで制御）
- **画像とアルバムの共有**：アクセスパスワード、有効期限、最大アクセス回数を指定して共有リンクを生成できます。公開共有ページは `/s/{token}` です
- **お知らせと独立ページ**：管理者はお知らせ（固定表示と重要度に対応）を公開してダッシュボードに表示し、`/p/{slug}` で公開アクセスできる独立ページを管理できます
- **通報管理**：ユーザーは画像を通報でき、管理者は管理コンソールで対応または却下できます
- **プランと課金**：プラン（価格、有効期間、クォータ、ロールグループ）とクーポン（固定額／割合、最低金額、利用回数、有効期間）、注文、注文管理、差し替え可能な決済チャネル
- **公式決済連携**：Alipay 対面決済（RSA2 署名／検証）と WeChat Pay v3（SHA256-RSA 署名、AES-GCM コールバック復号）、および手動・モックチャネル
- **画像の安全性**：差し替え可能なアップロードコンテンツスキャナを搭載し、ホワイトリストと危険なマジックナンバー検出を内蔵。画像に偽装した実行可能コンテンツを拒否します
- **通知システム**：SMS とメールはプラグイン経由で送信します。組み込みのログ／HTTP SMS プラグインと SMTP メールプラグインはデフォルトで信頼され、サンドボックス不要で、管理コンソールからテスト送信できます
- **組み込み／外部プラグイン**：組み込みプラグインはホストとともにコンパイルされ、プロセス内で動作します。外部プラグインは WASM サンドボックスでの実行が必須です。管理画面のプラグインマーケットプレイスで、インストール、設定、テスト、使用中チャネルの切り替えを一括管理できます
- **チケットシステム**：ユーザーはチケットを送信してサポートに連絡でき、管理者は返信してクローズできます
- **ランダムなストレージキーと重複排除**：保存ファイルには日付で分割されたランダムで推測不可能なキーを使用します。コンテンツの `sha256` は別途保存され、同じ所有者が同一コンテンツをアップロードした場合は自動的に重複排除されます。所有者が異なる場合はそれぞれ独立したオブジェクトを保持します
- **元のファイル名を保持**：ストレージ層ではランダムな名前のファイルを使用し、データベースには元のファイル名、保存ファイル名、ハッシュを別々に記録します
- **複数の画像処理ドライバー**：Pure Go（デフォルト）、libvips（`-tags libvips`）、ImageMagick（`magick` コマンド）の 3 種類に対応。実行時に設定に応じて選択し、利用できない場合はフォールバックします
- **オンデマンド画像処理**：URL クエリパラメータによるリアルタイムのリサイズ、クロップ、回転、反転、グレースケール、ぼかし、シャープ化、テキストウォーターマーク、トランスコードに対応し、ETag キャッシュを使用します
- **複数のストレージバックエンド**：ローカルファイルシステム、S3 互換オブジェクトストレージ（AWS S3 / MinIO / Cloudflare R2）、Alibaba Cloud OSS、Tencent Cloud COS、Qiniu Cloud Kodo
- **実行中のストレージ切り替え**：管理コンソールからいつでもデフォルトストレージを切り替えられます。既存の画像は記録に基づいて元のストレージから自動的に読み込まれるため、再起動は不要です
- **ストレージプール**：複数のストレージバックエンドをプールにまとめ、重み付きラウンドロビンまたは優先度ポリシーで新しいオブジェクトを配置します。プールは書き込みにのみ影響し、既存の画像は引き続き記録に基づいて読み込まれます
- **選択可能なデータベース**：SQLite（デフォルト、すぐに利用可能）、PostgreSQL、MySQL 5.7+（MariaDB 互換）
- **アルバムと画像広場**：アルバムで画像を整理できます。画像とアルバムの両方を公開でき、ユーザーをまたぐ画像広場と公開アルバム一覧に表示されます。ユーザーの公開プロフィールページも提供します
- **ロールグループと複数ポリシー**：ロールグループごとにユーザーのストレージクォータ、アップロード制限、レート制限、画像処理機能、機能スイッチを制御します。ポリシーは再利用可能で、種類ごとに上書きできます。登録ユーザーは自動的にデフォルトのロールグループに参加します
- **アカウント体系**：管理者と一般ユーザーは別テーブルで管理します。JWT セッション + 長期 API トークン
- **画面の分離とセットアップモード**：公開トップページ + ユーザーセンター（`/user`）と管理コンソール（`/admin`）を分離。低権限の Guest ビジターと、`/install` を手動で開くセットアップモードを内蔵
- **UI の国際化**：フロントエンドは vue-i18n により中国語・英語・日本語を提供します。Element Plus の組み込み文言、ページタイトル、言語設定も連動して切り替わります
- **クォータとレート制限**：ユーザーごとのストレージクォータ、ユーザー／Guest／IP ごとのレート制限
- **セキュリティ**：AES-256-GCM による秘密情報の暗号化保存、bcrypt パスワード、多層防御のレスポンスヘッダー

| フロントエンド | Vue 3、Pinia、Vue Router、Element Plus、TypeScript、Vite |

## クイックスタート

### 要件

- Go 1.26 以降
- Node.js 22+ と pnpm 9（フロントエンドのビルドに必要。フロントエンドを埋め込んだ Docker／CI バイナリを使用する場合は不要）

フロントエンドの成果物は**リポジトリにコミットされません**。ビルド時に `internal/webui/dist` へ生成されます。`make build` はフロントエンドをビルドしてからバックエンドをコンパイルします。Node 環境なしでバックエンドのみをビルドする場合は、`internal/webui/dist` を用意して（CI／リリース成果物など）`make build-go` を実行してください。

### ビルドと実行

```bash
# 完全ビルド（フロントエンド + バックエンド）。成果物は bin/axmipic
make build

# バックエンドのみビルド（既存の internal/webui/dist を再利用。未配置の場合 Web UI は 503 を返します）
# make build-go

# フロントエンドのみビルド
# make web

# サンプル設定で実行
cp configs/config.example.yaml configs/config.yaml
./bin/axmipic -config configs/config.yaml
```

直接実行する場合：

```bash
make run            # フロントエンドをビルドしてから go run ./cmd/axmipic -config configs/config.example.yaml
```

デフォルトでは `0.0.0.0:8080` で待ち受けます。`http://localhost:8080` を開くとコンソールにアクセスできます。

ローカルでフロントエンドを開発する場合は HMR を有効にできます（デフォルトは無効）。`web/` で `pnpm dev` を実行し、設定ファイルで `web.hot_reload.enabled: true` を指定します（`target` のデフォルトは `http://127.0.0.1:5173`）。その後 `http://localhost:8080` を開くと、再ビルドなしでフロントエンドがホットリロードされます。詳細は[設定](https://axmipic.gpcn.cc/ja/guide/configuration)を参照してください。

### 管理者の作成

方法は 2 つあります。

1. **設定ファイルによるシード（推奨）**：`configs/config.yaml` に `auth.bootstrap_admin: "ユーザー名:パスワード"` を設定します。admins テーブルが空の場合にのみ有効になります：

   ```yaml
   auth:
     bootstrap_admin: "admin:強力なパスワード"
   ```

2. **管理コンソールから作成**：既存の管理者でログインし、**ユーザー管理 → 管理者** タブで新しい管理者を作成します。

> 初回デプロイ時は、管理者が存在しない状態を避けるため、起動前に `auth.bootstrap_admin` を設定することをおすすめします。登録導線では一般ユーザーのみが作成されます。

## Docker で実行

```bash
docker run -d --name axmipic \
  -p 8080:8080 \
  -v axmipic-data:/app/data \
  -e AXMIPIC_SERVER_BASE_URL=http://localhost:8080 \
  -e AXMIPIC_AUTH_BOOTSTRAP_ADMIN="admin:強力なパスワード" \
  ghcr.io/axmishell/axmipic:latest
```

詳細（イメージビルド、GHCR、Docker Compose、セットアップモード）は [Docker デプロイ](https://axmipic.gpcn.cc/ja/guide/deployment)を参照してください。
