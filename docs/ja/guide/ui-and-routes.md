# インターフェースとルート

フロントエンドはロールによって 3 つのインターフェースに分かれており、組み込みのセットアップモードも用意されています:

| パス | 対象 | 説明 |
|------|----------|-------------|
| `/` | すべての訪問者 | 公開ランディングページ: ブランドページ + 画像アップロード（ドラッグ＆ドロップ/クリック/ゲストも利用可能）+ 画像広場プレビュー + ログイン/ユーザーセンターへの入口 |
| `/user/*` | 一般ユーザー | ユーザーセンター: マイ画像、画像処理、アルバム、画像広場、共有、トークン、プラン、チケット、アカウント設定 |
| `/admin/*` | 管理者 | 管理者コンソール: ダッシュボード、ユーザー管理、画像広場、サイトコンテンツ、ロールポリシー、課金管理、ストレージ設定、システム設定、メールログ |
| `/login` | すべてのユーザー | 一般ユーザーのログイン / 登録 |
| `/admin/login` | 管理者 | 管理者専用のログインページ。セキュアエントリが有効な場合はエントリ Cookie がある場合のみアクセス可能で、それ以外は 404 |
| `/admin/entry/<token>` | 管理者 | 管理者セキュアエントリ。検証後、10 分間有効なエントリ Cookie を設定して `/admin/login` へリダイレクト |
| `/install` | 未初期化のインスタンス | セットアップモード（初期化が完了すると 404 を返す） |

ログイン後、ユーザーはロールに応じてリダイレクトされます。一般ユーザーは `/user`、管理者は `/admin` へ移動します。一般ユーザーが `/admin/*` にアクセスすると `/user` へリダイレクトされ、未認証の訪問者が `/admin/*` にアクセスすると専用の `/admin/login` へ送られます。管理者はコンソールのサイドバー下部または右上のアカウントメニューからユーザーセンター `/user` に入れます。ユーザーセンターにいる間は、同じ場所に `/admin` へ戻る「管理者コンソール」の入口が表示されます。

### 管理者セキュアエントリ

「システム設定 → 実行時設定 → 管理者セキュアエントリ」で有効化できます。有効化すると:

- `/admin/login` に直接アクセスできなくなり、サーバーは 404 を返します;
- 管理者コンソールが生成したセキュアエントリ `/admin/entry/<token>` にアクセスする必要があります;
- 検証に成功すると、エントリは 10 分間有効な `axmipic_admin_entry` HttpOnly Cookie を設定し、ログインページへリダイレクトします;
- 管理者ログイン API はこのエントリ Cookie を必要とし、ログイン成功後すぐにクリアされます;
- ログイン済みの管理者セッションは有効なままで、セキュアエントリの切り替えの影響を受けません;
- ページおよびログイン API への無効なエントリ試行はすべて 404 として処理されます。

セキュアエントリのトークンはアプリケーションのアクセスログに表示されません（`/admin/entry/[redacted]` として記録されます）が、リバースプロキシ/ゲートウェイ側でも完全な URL をマスクする必要があります。

## ゲストビジター

システムには組み込みの `Guest visitor` ロールグループがあります（クォータとアップロードサイズが小さく、画像広場、共有、トークンなどの機能はデフォルトで無効）。`auth.allow_guest_upload` が `true` の場合、未認証の訪問者はホームページからアップロードでき、Guest ロールグループのレート制限とクォータが適用されます。

すべての未知の訪問者が単一のクォータプールを共有してすぐに使い果たすことを避けるため、ゲストは**ブラウザごとに分離された** ID を使用します:

- 最初のアップロード時に、サーバーは訪問者用の**個別の Guest アカウント**を作成し、署名付き Cookie（`axmipic_guest`、HttpOnly）を発行します。同じブラウザからの以降のアップロードはそのアカウントを再利用し、それぞれが独自の `guest_quota_mb` クォータを持ちます。
- Cookie を変更すると新しいアカウントになるため、**IP ごとのウィンドウクォータ** `auth.guest_ip_quota_mb` も適用されます（デフォルトのウィンドウは 24 時間、0 は無制限）。クライアント IP のウィンドウ内のゲストアップロード総量がこの値を超えると、リクエストは拒否されます（HTTP 429）。これにより、Cookie を繰り返し変更してゲストごとのクォータを回避することを防ぎます。
- Guest アカウントは「ユーザー管理」に表示されず、ユーザー数にも含まれません。バックグラウンドジョブが期限切れの IP 使用記録と未使用の空の Guest アカウントを定期的にクリーンアップします。

> 注意: 組み込みのレガシー `guest` アカウントは互換性のため、および匿名の読み取り専用 API でのポリシー解決にのみ使用されます。匿名アップロードでは使用されなくなりました。Guest グループのクォータを調整するには、「運用 → ロールポリシー」の Guest visitor グループを変更してください。変更後、関連するアカウントのクォータは自動的に同期されます。

## セットアップモード

セットアップモードは独立したページで、ユーザーが**明示的に `/install` にアクセスする**必要があります。フロントエンドのルーティングは `/install` についてのみインストール状態を確認します。未初期化の場合はセットアップウィザードを表示し、初期化済みの場合は 404 を返します。`/` やその他のページにアクセスしても自動的にリダイレクトされません。

起動時に `install.lock_file`（デフォルト `./data/install.lock`）が存在しない場合、インスタンスは未初期化と見なされ、管理者とロールグループのシードがスキップされます。セットアップページを完了すると、次の処理が行われます:

1. データベースを検証して接続し、マイグレーションを実行します;
2. 管理者アカウントを作成します;
3. デフォルトのロールグループと `Guest visitor` ロールグループをシードします;
4. 組み込みの `guest` アカウントを作成します;
5. 設定ファイルと `install.lock` を書き込みます。

ロックファイルが存在すると初期化は完了と見なされ、セットアップエントリは閉じられます。再度 `/install` にアクセスすると、ログインページや管理者コンソールへリダイレクトされるのではなく 404 が返されます。セットアップでは管理者アカウント（`admins` テーブル）のみが作成されます。その後は `/admin` にアクセスしてログインしてください。通常の `/login` は `customers` テーブルに対して検証するため、そこで管理者アカウントを使用するとユーザー名またはパスワードが無効と表示されます。再初期化するには、`install.lock`（およびデータベース）を削除して再起動してください。関連 API:

| メソッド | パス | 説明 |
|--------|------|-------------|
| GET | `/api/v1/install/status` | セットアップ状態（ログイン不要） |
| POST | `/api/v1/install` | セットアップを実行（ログイン不要） |

`install.disabled: true` を設定するとセットアップチェックを完全にスキップします（テストやコンテナオーケストレーションに便利です）。

> `POST /api/v1/install` はセットアップトークンを必要とせず、初期化が完了したかどうかの判断に `install.lock_file` のみを使用します。デプロイ時は、セットアップを完了する前に公開インターネット上の他者にセットアップページへ先に到達されないようにしてください。`auth.bootstrap_admin` を設定してセットアップモードをスキップすることもできます。

## コンソールの操作規約

- **グローバル検索**: コンソールで `⌘K` / `Ctrl+K` を押すとページ検索が開き、矢印キーで選択、Enter で移動、`Esc` で閉じられます。トップバーにも入口があります。検索インデックスはサイドバーナビゲーション（`web/src/utils/navigation.ts`）と同じソースを共有し、メニューと検索の一貫性を保ちます。
- **サイドバーの折りたたみ**: デスクトップではトップバーからサイドバーを折りたためます（232px ↔ 56px）。折りたたみ状態は `localStorage` に保存されます。モバイルでは引き続きドロワーを使用します。
- **コンテンツ幅**: 管理者コンソールのコンテンツ領域は最大 1600px、ユーザーセンターは 1200px に保たれ、データ密度の高いページとフォームの読みやすさのバランスを取っています。
- **未保存の変更の保護**: システム設定の実行時設定タブは設定ドメインごとにダーティ状態を追跡し、固定の「すべて保存 / 変更を破棄」バーを表示し、ルートを離れるときやページを閉じるときに確認を促します。
- **リストのページネーション**: 注文、チケット、通報、通知ログはサーバー側ページネーションを使用します。設定リスト（プラン、ポリシー、ストレージなど）はサイズが限られているため全件読み込みします。
- **ユーザー名の変更**: 管理者と一般ユーザーの両方がアカウント設定ページで自分のユーザー名を変更できます。現在のパスワードが必要で、TOTP が有効な場合は動的検証コードも必要です。ユーザー名は表示時に入力どおりの大文字小文字を保持しますが、ログインと一意性チェックは大文字小文字を区別しません。変更後も現在のセッションは有効なままで、古いユーザー名は即座に使用できなくなります。
- **ユーザー管理の編集**: 管理者はユーザー管理で一般ユーザーまたは管理者のユーザー名とメールアドレスを編集でき、必要に応じてパスワードをリセットできます。メールアドレスを変更すると検証状態がリセットされます。パスワードのリセットは、対象ユーザーの既存セッションを即座に無効化するものではありません。
