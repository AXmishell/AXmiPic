# 認証

| メソッド | パス | 説明 |
|--------|------|-------------|
| POST | `/auth/register` | 一般ユーザーを登録します(メール認証コードが必要) |
| POST | `/auth/register/code` | 登録用の認証コードをメールアドレスに送信します(ログイン不要) |
| POST | `/auth/login` | 一般ユーザーのログイン(ユーザー名またはメールアドレス) |
| POST | `/admin/auth/login` | 管理者のログイン(専用のエントリーポイント) |
| POST | `/auth/totp/verify` | ログイン時の TOTP 二要素認証を完了します(`challenge_token` + `code`) |
| GET | `/auth/me` | 現在のアカウント情報 |
| GET | `/auth/security` | 現在のアカウントのセキュリティ設定状況(TOTP、メール) |
| POST | `/auth/totp/setup` | TOTP シークレットを生成し、`secret` と `otpauth` リンクを返します |
| POST | `/auth/totp/enable` | 動的コードを検証したうえで二要素認証を有効にします |
| POST | `/auth/totp/disable` | 二要素認証を無効にします(動的コードまたはパスワード) |
| POST | `/auth/email/code` | 対象のメールアドレスに認証コードを送信します(1 分あたり 1 回、アカウントごとに 1 日 10 回まで) |
| POST | `/auth/email/verify` | コードを検証してメールアドレスをバインドします。別のメールアドレスへの変更には現在のパスワードが必要です |
| POST | `/auth/email/unbind` | メールアドレスのバインドを解除します(現在のパスワードが必要) |
| POST | `/auth/password` | 現在のアカウントのパスワードを変更します(`current_password`、`new_password` が必要) |
| POST | `/auth/password/reset/code` | 認証済みのメールアドレスにパスワードリセットコードを送信します(ログイン不要) |
| POST | `/auth/password/reset` | コードを検証してパスワードをリセットします(ログイン不要) |

TOTP を有効にすると、`/auth/login` と `/admin/auth/login` はセッションを直接返さなくなり、代わりに
`{"totp_required": true, "challenge_token": "…"}` を返します。クライアントはこのトークンと認証アプリが生成した
6 桁のコードを指定して `/auth/totp/verify` を呼び出し、完全なセッションと交換する必要があります。TOTP シークレットは
保存前にマスターキーで暗号化され、ログインチャレンジトークンは独自のスコープを持ち、セッションとして使用できません。
メールのバインドは、認証コードによってアドレスが実際に到達可能であることを証明します。実際のメールチャネルが
設定されていない場合、コードはサーバーログへの出力にフォールバックします。

一般ユーザーと管理者のどちらも、上記のセキュリティ機能を利用できます。

メール再バインドのポリシー: バインドと再バインドは同じ送信/検証エンドポイントを共有します。再バインドでは新しい
メールアドレスの検証のみが必要ですが、**対象のアドレスが現在認証済みのものと異なる場合は、現在のパスワードを
提供する必要があります**。再バインドが成功すると、旧アドレスに変更通知が送信されます。認証コードの送信は
アカウントごとにレート制限され(1 分あたり 1 回、バースト 2 回、1 日あたり最大 10 回)、上限を超えると
HTTP 429 を返します。コードの有効期間は 10 分で、1 回限り有効、試行は最大 5 回までで、他のアカウントに
すでにバインドされているアドレスと競合した場合は HTTP 409 を返します。コードと日次の送信カウンターは
データベースに永続化されるため、サービスの再起動やマルチインスタンス構成でも一貫性が保たれます。

パスワード管理: サインイン済みのユーザーは、現在のパスワードを添えて `POST /auth/password` を呼び出すことで
パスワードを変更できます。パスワードを忘れた場合は、`POST /auth/password/reset/code` を呼び出して認証済みの
メールアドレスにコードを送信し、その後コードを添えて `POST /auth/password/reset` を呼び出し、新しいパスワードを
設定します。アカウントの列挙を防ぐため、未登録のアドレスへのリクエストも実際にはメールを送信せずに成功を返し、
リセット時には未登録のアドレスと誤ったコードが同じエラーを返します。

登録とメールログイン: 一般ユーザーを登録するには、まず `POST /auth/register/code` を呼び出してメールアドレスに
認証コードを送信し(アドレスがすでに使用されている場合は HTTP 409 を返します)、次に `username`、`email`、
`code`、`password` を添えて `POST /auth/register` を呼び出して登録を完了します。登録が成功すると、そのアドレスは
認証済みとしてマークされます。ログイン時、`POST /auth/login` の `username` フィールドにはユーザー名または
メールアドレスのいずれかを指定できます。管理者アカウントは管理者コンソールまたはブートストラップ設定から作成され、
この登録フローは経由しません。

ログイン識別子の曖昧さを避けるため、ユーザー名とメールアドレスは同じアカウントテーブル内で決して衝突しません。
ユーザー名は他のユーザーのメールアドレスと一致できず、メールアドレスも他のユーザーのユーザー名と一致できません
(ログイン時はまずユーザー名を検索し、次にメールアドレスを検索します)。
