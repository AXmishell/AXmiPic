# 画像広場の AI モデレーション

アップロードされた画像が「画像広場に公開」される(公開状態になる)前に、ビジョンモデルを呼び出してコンテンツモデレーションを実行できます。モデレーションは**画像広場にのみ適用されます**。モデレーションに失敗した画像は公開されず、ユーザー自身の非公開画像として残ります。

設定方法は 2 つあり、**データベースの設定が優先されます**:

1. **管理者コンソールでのオンライン設定(推奨。再起動なしで即時反映)**: 「システム設定 → AI モデレーション」ページ、または `GET/PUT /api/v1/admin/moderation`。キーはマスターキーで暗号化されてデータベースの `settings` テーブルに保存され、API は設定済みかどうか(`api_key_set`)のみを返します。
2. **設定ファイル / 環境変数(初回起動時のフォールバック)**: `moderation.*` セクションまたは `AXMIPIC_MODERATION_*`。データベースにレコードがない場合、ここから初期化されてデータベースに書き込まれます。

| 設定 | 説明 |
|---------|-------------|
| `moderation.enabled` | 画像広場の AI モデレーションを有効にするかどうか |
| `moderation.base_url` | 標準的な OpenAI 互換 API のルート URL。例: `https://api.openai.com/v1` |
| `moderation.api_key` | API キー(Bearer)。オンラインで保存する際に空にすると既存のキーを維持します |
| `moderation.model` | ビジョンモデル名。例: `gpt-4o-mini` |
| `moderation.timeout_sec` | 1 回のモデレーションリクエストのタイムアウト(秒。デフォルト 30) |
| `moderation.prompt` | デフォルトのモデレーションプロンプトを上書きします(デフォルトではモデルは `SAFE` または `UNSAFE` のみを回答する必要があります) |
| `moderation.max_image_mb` | モデレーションに送信する画像の最大サイズ(MiB。デフォルト 10)。これより大きい画像は失敗として扱われます |

動作とフォールバック:

- `POST /api/v1/images/batch` で画像を公開する場合、それぞれ個別にモデレーションされます(同時実行数の上限は 4)。合格したものは公開され、失敗したものは強制的に非公開のままになります。レスポンスには `published` と `blocked`(ブロックされた画像の ID)が含まれ、フロントエンドはこれを使ってユーザーに通知します。
- **フェイルクローズ**: モデルが空のコンテンツや認識できない結果を返した場合、または API 呼び出しが失敗した場合(ネットワーク/タイムアウト/非 200)、モデレーションは常に失敗として扱われ、画像は非公開のままになります。
- すでに公開されている画像は再度モデレーションされません。画像を非公開に設定してもモデレーションはトリガーされません。
- このモデレーションは「公開前」のゲートであり、アップロード自体を変更しません。画像は常にまず非公開で保存されます。
- 管理者コンソールで保存すると、実行中のモデレーターが即座に再構築されます。再起動は不要です。

例:

```yaml
moderation:
  enabled: true
  base_url: "https://api.openai.com/v1"
  api_key: "sk-..."
  model: "gpt-4o-mini"
  timeout_sec: 30
  max_image_mb: 10
```
